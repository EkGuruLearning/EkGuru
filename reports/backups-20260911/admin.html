EkGuru — bookings

Private tool. noindex, never linked from the site. Anyone with the URL can open it, so treat it as unlisted, not secret.

Closing the tab locks it automatically.
What this page does and does not protect. GitHub Pages serves every file in the repository, so this URL is reachable by anyone who knows it — a passcode gate is a lock on the door, not a vault. What matters is that the booking records are not in the repo: they live in this browser's local storage only. Someone opening this page on their own machine sees an empty dashboard. Keep the passcode long, and export your CSV regularly.
The honest picture on databases. GitHub has no built-in database — GitHub Pages serves files and nothing else, no server, no SQL. So there are three layers instead, and together they do the job:

1. FormSubmit archive — a real server-side database. Every booking sent through the site is already stored there, timestamped, for 30 days. Read it below with a key.
2. This browser — every booking made or tested on this device is kept in local storage.
3. Your export — the CSV button below. Do that monthly and the 30-day limit stops mattering. That file is yours permanently.

Write a new page from the spreadsheet

Tab 1 controls the four tutors. Tab 2 makes pages. One row becomes a real page under /answers/ with schema, breadcrumbs and a sitemap entry — no code change.

ColumnWhat to write
slugthe URL — lowercase-with-hyphens
questionthe exact phrase someone types into Google
answer2–3 sentences. Google lifts this as the snippet. 200 characters minimum
bodythe fuller answer. Blank line = paragraph. ## heading, - bullet, **bold**. 400 characters minimum, or leave empty
keywordscomma separated
relatedslugs of other rows
statuslive or draft — only live is published
The minimum lengths are not a suggestion. A row shorter than that is refused by the build, on purpose. Thin pages made at scale are what Google calls doorway pages, and a penalty would take the other 101 pages down with them. One real answer beats fifty stubs.

Are the relays alive right now?

This asks the internet, not our own code. Each relay is contacted with a request that cannot send an email and cannot spend quota. Reached means the service answered; it does not prove it will deliver. Only the relay you own reports a real remaining count.

What a message costs

Two rules decide every route. (1) Only one relay can deliver to somebody we have never emailed, and it is capped. (2) Mail to an inbox you own must never spend one of those — the free relay reaches your own activated inbox forever at no cost.

Send to many people at once

One message, many recipients, sent one at a time so no relay throttles the burst. Each recipient is routed independently — the cheapest relay that can actually reach them. Write {{name}} anywhere and it becomes that person's name.
